### 3. Webhook & Endpoint Security Audit

1. **Meta WhatsApp Webhook (`GET /api/v1/whatsapp/webhook`):**
   - Validates `hub.mode == "subscribe"` and `hub.verify_token`.
   - Correctly echoes `hub.challenge` as `text/plain`.
   - Returns HTTP 403 Forbidden on invalid verify token.
2. **Meta WhatsApp Webhook (`POST /api/v1/whatsapp/webhook`):**
   - Enforces HMAC-SHA256 payload verification against `X-Hub-Signature-256` using `WHATSAPP_APP_SECRET`.
   - Deduplicates incoming messages via `wamid` cache to prevent duplicate reservation creations on webhook delivery retries.
3. **Twilio Voice Webhook (`POST /api/v1/voice/incoming` & `/interact`):**
   - Validates `X-Twilio-Signature` using HMAC-SHA1.
   - Emits schema-compliant TwiML XML (`application/xml`).
   - Implements automated human concierge escalation (`<Dial>+911140509900</Dial>`).
4. **Sentry PII & Credential Sanitizer (`sentry_before_send`):**
   - Redacts `Authorization`, `Cookie`, `X-Twilio-Signature`, `X-Hub-Signature-256`, `password`, `token`, `secret`, `jwt`, and `api_key`.
   - Redacts user emails (`[REDACTED_EMAIL]`) and truncates IP addresses to subnet blocks (e.g., `203.0.0.0`).

### 4. DEMO vs REAL Mode Safety

- In `DEMO` mode, transactional emails generated by `notification_service` include a prominent amber banner:
  > *"⚠️ DEMO SIMULATION NOTICE — This is an automated demonstration booking request. No actual restaurant reservation has been secured."*
- Reservation requests originating from WhatsApp or Voice in `DEMO` mode are tagged as `DEMO` records in the database.
- Pricing, menu options, and policies retrieved during chat or voice interactions strictly observe the active environment scope (`DEMO` vs. `REAL`).
